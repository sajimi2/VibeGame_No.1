```json
{
  "schema_version": 1,
  "session":     { "kills", "kills_required", "quest_stage", "current_level", "reward_paid" },
  "progression": { "level", "xp_in_level", "xp_to_next", "unspent_points", "bonus_max_health", "bonus_max_stamina" },

}
```

## 4. Windows 导出：**已完成并实际运行验证**

一度受阻，现已解决：

1. 首次实测确认阻塞：`export_templates/4.7.2.stable` 不存在，`--export-release` 退出码 1 并点名缺少 `windows_release_x86_64.exe`；Godot CLI 无安装模板选项。
2. 从官方 release 下载匹配版本的 `Godot_v4.7.2-stable_export_templates.tpz`（**1222 MB，用时 689 秒**）并解包到 `%APPDATA%\Godot\export_templates\4.7.2.stable`（35 个文件，含 `windows_release_x86_64.exe`）。
3. 导出命令与结果：
```
$ godot --headless --path <project> --export-release "Windows Desktop" builds/windows/OutpostRPG.exe
EXPORT_EXIT=0
builds/windows/OutpostRPG.exe   104.1 MB
builds/windows/OutpostRPG.pck     0.5 MB
```
（注意：导出输出目录必须**预先存在**，否则报「给定的导出路径不存在」。）

4. **实际运行了导出的 EXE**：进程启动、窗口标题 `Outpost RPG`、客户端区域 1280×720（= 640×360 视口的 2 倍，与配置一致）。
5. **中文字体验证**：截图 `work/exported_build_frame.png` 可见「村庄 · 安全点（进入即回满状态）」「（附近无敌人）」「契约：未接（0/3）」「+5 最大生命 / +5 最大体力」「WASD 移动 | 左键 轻击 …」——导出包内中文字体正常，无方块缺字。
6. **输入验证**：向前台窗口发送 `D`（右移）与 `A`（左移）虚拟键，进程保持响应且未崩溃。
7. **素材验证**：`.pck` 内含 12 个物品 `.tres` 等资源，场景可加载、可游玩。
8. **实际运行中发现并修复了一个只在导出包暴露的信号错误**：走入关卡出口触发换场景时，新场景的 `Area2D` 在**信号回调中**设置 `monitoring`/`monitorable` 被 Godot 拒绝（`Function blocked during in/out signal`）。修复：`ActorHurtbox`、`LevelExit`、`QuestGiver` 改用 `set_deferred()`。修复后重新导出，再次走动跨关，导出的 `godot.log` **为空**（无任何错误），进程保持存活。
9. **存档在导出版内已端到端验证**：加了一个默认关闭的启动自检开关（`LevelFlow.run_save_smoke_check`），开启后导出版启动时会自己走一遍「存档 → 读档」并把结果写进 `user://save_smoke.log`。实测输出：
```
exported save path: C:/Users/21775/AppData/Roaming/Godot/app_userdata/Outpost RPG/outpost_save.json
save_now ok=true message=''
file exists after save: true
load status: 0            (0 = OK)
health before=100.0 after reload=100.0
loaded in level: village
```
即：导出版能写入自己的 `user://`、存档文件确实生成（737 字节）、读档返回 OK 并回到村庄。验证后该开关已设回 `false` 并重新导出，确认正式导出版启动时**不会**自建存档、`godot.log` 为空。

结论：**Windows 导出已完成并实际运行验证**，存档在导出版内也能工作，不再阻塞。
