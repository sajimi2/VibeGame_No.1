## 2. 接口变更

`ActorCommandPort` 追加：

```gdscript
## World-space unit vector the actor currently faces. Downstream code (hitboxes,
## block arcs, T02) reads facing from here, never from a visual node.
@abstract
func get_facing() -> Vector2
```

原因：`set_intent` 的契约写明“零方向保留上一次非零朝向”，朝向因此是端口的内部状态，但契约没有任何读取口。T01 需要它来驱动朝向箭头，T02 的命中框/格挡弧更必须从端口取朝向而不是从视觉节点取。

为何不写 CHANGE_REQUEST：这是纯追加，既有两个抽象方法签名、数据对象字段、信号均未改动，也不影响任何现有调用方或存档格式。若 Codex 判定需要走正式流程，我会补一份并把该改动纳入其中。

## 6. 未验证内容及原因

1. **真人键鼠操作**：WASD 实际按键、真实鼠标移动瞄准、窗口缩放下的瞄准观感。沙箱无法产生真人输入，程序化注入的坐标空间与硬件事件不同（见上）。这是 T01 最关键的手感项，必须由用户试玩确认。
2. **相机平滑跟随的观感**：`FollowCamera` 开启了 `position_smoothing_enabled`（速度 10）。数值未做手感调优，只是让跟随不抖动；平滑是否舒服未验证。
3. **斜向推墙时的滑动手感**：实测 `move_and_slide` 会丢弃被阻挡轴并重新归一化剩余运动，因此贴墙斜推时自由轴几乎保持全速（实测 1.4757/1.5 像素每帧，98.4%），而不是几何投影的 1/√2。这是引擎既有行为，规格未规定，我未改动；是否符合预期的“贴墙滑行”手感需要用户确认。
4. **最小窗口尺寸下的可读性**：1920×1080 与 160×90 都只验证了速度不变，未评估 160×90 下画面是否可辨认。
5. 未在 macOS/Linux 上运行（项目目标是 Windows）。
