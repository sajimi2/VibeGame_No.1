## 1. 交付内容（对应 HANDOFF 的 5 步）

### 1.1 参数集中到 Resource
| 文件 | 内容 |
|---|---|
| `scripts/actors/actor_tuning.gd` | 一个 actor 种类的全部数值：移动/闪避、生命/体力/回复、护甲/阵营、受击硬直/破防硬直/击退阻尼、两个攻击 spec、闪避体力 |
| `scripts/combat/attack_spec.gd` | 单次攻击的数值：伤害、体力、前摇/有效/收招、判定盒尺寸与前瞻偏移、破防体力、硬直、击退 |
| `data/player_tuning.tres`、`data/attack_light.tres`、`data/attack_heavy.tres` | 玩家与轻重击（DESIGN.md 数值） |
| `data/bandit_tuning.tres`、`data/bandit_attack.tres` | 盗匪（保守值，见第 4 节） |
| `data/dummy_tuning.tres` | 木桩（无速度、无体力、team 3） |

UI、AI 与动画回调中不再有散落常量；T01 的 `SPEED_PIXELS_PER_SECOND` 常量已删除。

### 1.2 CombatantPort 与动作状态机
- `scripts/actors/actor_combatant.gd`（`CombatantPort` 实现）：生命/体力的唯一所有者，也是**唯一**的命中结算入口。处理闪避无敌窗、正面格挡、破防、护甲、`max(1, raw-armor)`、死亡一次性、伤害不治疗、按 `(source_id, attack_id)` 去重、体力原子扣除与延迟回复。
- `scripts/actors/action_rules.gd`（纯函数）：合法转换、各阶段时长、哪些状态可输出/可受伤/暂停体力回复。
- `scripts/actors/actor_action_port.gd`（重写 T01 实现）：IDLE/MOVE/WINDUP/ACTIVE/RECOVERY/DODGE/BLOCK/STAGGER/DEAD 全状态。动作开始**支付一次**体力；不足或忙碌一律拒绝且无副作用；攻击期间锁定朝向；同一步内不缓冲。
- `scripts/combat/actor_hitbox.gd`：仅在端口报告 ACTIVE 时用物理空间查询开判定盒，命中交给目标 `receive_hit`，每个 `attack_id` 每目标最多一次。
- `scripts/combat/actor_hurtbox.gd`：受击标记层（layer 4），不含任何伤害逻辑。

### 1.3 近战盗匪
`scripts/actors/bandit_controller.gd` + `scenes/bandit.tscn`：只通过自己的 `ActorCommandPort` 行动（与玩家输入适配器同一契约），**从不直接改玩家生命**。接近 → 进入距离 → 前摇（武器后拉）→ 有效（前刺）→ 收招 → 冷却；卡墙时有界侧绕。

### 1.4 HUD 与死亡重试
- `scripts/ui/combat_hud.gd`：只读端口信号，绘制玩家 HP/体力、敌人 HP、状态文字与操作说明；不计算伤害、不发奖、不写端口。
- `scripts/world/arena_flow.gd`：接线盗匪目标；R 键（新增 InputMap 动作 `restart`）重开一局——原地复位双方位置/生命/体力/状态，不清除场景。
- `scenes/arena.tscn`：加入木桩(360,430)、盗匪(600,430)、HUD；玩家出生点不变。
- `scenes/training_dummy.tscn`：静止木桩，只闪白反馈，不还手。

### 1.5 输入与调度
一次物理步的顺序由 `process_physics_priority` 固定：
`InputAdapter(-100) → ActorActionPort(-50) → ActorCombatant(-10) → ActorHitbox(-5) → PlayerController(0)`，
盗匪为 AI 直接用同一契约。T01 的输入时序测试仍然通过。

## 3. 验收结果与证据

自动（`tests/t02_combat_test.gd`，82 项）：

| 验收项 | 证据 |
|---|---|
| 体力拒绝无副作用 | 0/负数/不足时 `try_spend_stamina` 返回 false，体力与状态与 attack_id 全部不变；拒绝后不补发 |
| 重复命中 | 一次轻击对同一目标只造成一次 18 点伤害（跨整个有效窗与收招） |
| 前摇/收招不伤人 | WINDUP 与 RECOVERY 阶段目标生命不变 |
| 无敌窗边界 | 闪避 0.02s 前受击正常受伤；0.12s 内受击 DODGED 且 0 伤害；0.25s 后受击正常受伤 |
| 正背面格挡 | 正面 BLOCKED、生命不变、消耗 16 体力；背后 DAMAGED 且满额 18 伤害 |
| 破防 | 体力不足时 GUARD_BROKEN、承受全额伤害、进入 STAGGER |
| 死亡一次性 | `died` 恰好 1 次；死后命中 IGNORED；死后拒绝动作且不再移动；生命保持 0 |
| 状态机合法转换与锁定 | 拒绝二连击/中途闪避；朝向在攻击期间锁定；RECOVERY 后回到 IDLE 才能再出招 |
| 敌人闭环 | 盗匪确实接近（相遇距离缩小）、出现 WINDUP、玩家生命下降；玩家反击能扣盗匪血量 |
| 死亡重试 | 双方死亡后 `restart()` 复原生命/位置/状态；重开后盗匪能再次接敌 |

## 5. 未验证内容及原因

1. **真人键鼠试玩**：沙箱无法产生真实硬件输入。所有"操作"均为程序化注入或让 AI 自跑，**不等于手感确认**。
2. **主观手感**：轻重击节奏、闪避距离与无敌窗、格挡收益、盗匪威胁度、击退力度，均未由用户确认。
3. 暂停菜单、背包、多显示器/DPI、动画素材——按交接明确不做。
4. T07 的存档与导出未开始。
5. 未在 macOS/Linux 运行。

## 6. 已知问题

- 盗匪寻路是"朝玩家直走 + 卡住时有界侧绕"，不是寻路算法。障碍复杂时可能绕远（实测在开阔区正常接敌，见第 3 节）。T03 有多敌人时可再评估。
- 场景里的木桩是静止靶，不参与遭遇计数；T03 的遭遇系统接管敌人组合后会重新安排。
- `restart` 是原地复位而非重载场景。T07 需要真正的流程时再替换。
- 盗匪没有格挡/闪避动作（spec 里有但 AI 不用），T03 再加。
- HUD 的 ProgressBar 使用默认主题外观（灰底），未做视觉调优；数值本身正确（截图与第 3 节数值一致）。
