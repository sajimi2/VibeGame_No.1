## 4. 未验证内容及原因

1. **真人试玩完整流程**：全部为程序化验证。20～30 分钟的实际通关时长、关卡节奏、头目难度均未由用户确认。
2. **音效已补做（程序生成，非外部素材）**：`scripts/ui/sfx_player.gd` 用代码合成 16bit PCM 短音（挥砍/命中/格挡/死亡/拾取/升级），每关一个共享 `Sfx` 节点；玩家出招、敌我受击/格挡/死亡都会播放。因为不引入任何外部文件，**无需素材授权记录**。真实听感（音量、音色、是否刺耳）未由用户确认，也没有做音量平衡或音频总线配置。
3. **像素资产**：T06 要求「统一像素视觉」，我统一了尺寸基准与色板，但仍是几何占位，未换正式像素图。
4. 未在 macOS/Linux 运行。

## 5. 实现选择说明

1. **没有用 Autoload**：ARCHITECTURE 明确「第一版不需要 Autoload 单例」。`GameSession` 用**静态 var current** 在关卡间共享，由 `LevelFlow` 在 `_ready` 里确保存在（直接 F5 跑某一关也能自动开一局）。
2. **关卡切换自己实现**：原来用 `SceneTree.change_scene_to_file()`，实测连续切换时第二次会把场景树清空（`current_scene` 变 null）。改为显式「先 add 新场景 → 设 current_scene → 再 queue_free 旧场景」，顺序确定且可测。
3. **出口用数据描述**：`LevelExit` 的 `destination` / `requires_quest_progress` / `requires_cleared_level` 都在场景里配置，上层出口就是这样锁住直到契约可交付且本层清空。
4. **头目复用盗匪控制器**：TASKS.md 说头目「使用既有行为组合」。我用 `boss_tuning.tres` 放大数值并启用突进，没有新写一套 AI。
5. **`arena.tscn` 仍在**：它没有被主场景引用，但被 `t02_combat_test` 等测试使用。按 Codex 早前对 `bootstrap.tscn` 的意见，我没有为了整洁去删它。

## 6. 已知问题

- 关卡是矩形房间，没有过渡动画/淡入；切换是瞬时的。
- `level_outpost_upper` 的出口需要「本层清空」，而头目死亡后尸体要 1.1s 才清除；清空计数用存活敌人，因此出口会在头目倒下后立即开启（不受尸体影响）。
- 升级面板常驻显示（未做「升级时才弹出」）。
- 掉落物会跨关卡留在原地（属于地面物体，不随场景切换保留，切场景即消失）。
