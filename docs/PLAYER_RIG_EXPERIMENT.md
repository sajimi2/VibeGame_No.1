# 三维角色源资产与离线烘焙

当前 F5 玩家、守卫和弓手均使用新管线；原玩家样板已扩展为三角色完整当前动作。工作在 codex/player-baked-rig，尚未提交/推送，也不表示用户已完成手感验收。已推送回退点为 86efa8a。

## 入口

- 正式游戏：F5。
- 原尺寸图集：打开 tools/art_preview.tscn 按 F6，默认是「玩家 · 三维烘焙」，另有守卫、弓箭手。选择动作、相对移动方向、持械和显示层，可逐帧/播放/导出。
- 独立对照：tools/player_rig_lab.tscn F6；1 轻装，2 重刀，Tab 原二维对照，M 实体源模型。不读写真实进度。

## 改造型和动作

源场景在 assets/characters/，分别为 player_rig.tscn、guard_rig.tscn、archer_rig.tscn。同名的 15 骨骼 Skeleton3D、衣服、护甲、头部、四肢是可编辑实体网格和材质；不再按旧二维像素关节拉伸网格。三者共用 humanoid_moves.tres 中的 64 个标准骨骼动画片段。

在 Godot 打开源场景，选 AnimationPlayer，在动画面板选择片段（例如 heavy_swing、run_00）。旋转骨骼、插入关键帧并保存共享动画资源，随后重新烘焙。同骨架角色也会得到动作更新。run_00 是身体前方移动，run_06 是后退，其余每格相差 30°；十二个**移动方向**的片段处理脚步与人体朝向差异，镜头下十二个**观察方向**仍由烘焙器旋转出图。

动画时间统一为 0～1 的动作相位；真实秒数、命中窗口和刀刃角度仍由 data/actions / 武器数据管理。普通肢体只旋转，骨长来自骨架 rest；骨盆允许移动。请不要给肢体插缩放轨道。较大比例调整还需检查手脚接触位置，不宣称自动重定向任意体型。

tools/create_humanoid_sources.gd 仅用于最初建模和关键帧初稿。初稿使用固定骨长 IK，结果保存为标准动画；**普通出图不执行生成器，也不调用旧 character_pose.build()**。已有源动画时默认拒绝覆盖；--replace-authored 会重建模板，不能用作日常刷新。

跑步由骨盆小幅移动、骨盆与胸椎协调倾斜、抬腿回收和摆臂组成；后退减小倾角和步幅。十二移动方向的胸椎倾角均小于 8°。重型/双手武器保持持握；轻装摆臂来自步态。主体采用刚性骨段，尚非 Blender 软蒙皮。

## 重新烘焙

保存源场景和动画后，在工程目录执行：

    & 'D:\vibe coding\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe' --path 'D:\vibe coding\OutpostRPG' --disable-vsync --script res://tools/bake_player_rig.gd

脚本保留旧名，默认已烘焙三角色；末尾加 -- player / -- guard / -- archer 可仅更新一个。烘焙需要 GPU，不能加 --headless。完成后等待编辑器导入 PNG；自动化可运行 --headless --editor --import，再启动游戏。输出位于 assets/characters/<角色>_baked/，模型、动画、工具与输出一起版本管理；不依赖 work 文件。

当前动作包括戒备、步行/疾跑、蹲起/蹲行、跳跃、匕首两招、宝剑两招、重劈、剑盾两招、拉弓、受击及死亡。每个角色只打包自己的攻击动作。敌人准备了蹲跳步态，不等于新增其 AI 行为。

## 数据流与性能边界

源场景 + AnimationLibrary → humanoid_rig 采样/上下身组合 → bake_player_rig → PNG 颜色/深度 + atlas.json → baked_human

- baked_human_spec 统一作业清单、帧键与选帧规则。
- 上下身以骨盆拼接，避免所有攻击相位乘以所有步态。站立攻击使用支撑步，移动攻击使用行走腿；蹲/跳攻击共用攻击上身并随骨盆移动，没有每招的全身特化变体。
- 双手三维位置与帧一起保存。玩家战斗沿用 grip_pixel/grip_depth 接口；盾使用另一只手，弓使用左手。不改变伤害、命中和存档。
- 玩家 19332、守卫 9324、弓手 7956 个分层帧。相同颜色与深度合并存储，共 9 组 1024² 颜色/深度页，RGBA8 原始像素约 **72 MiB**，不含元数据、引擎与驱动开销。
- 同类角色共享图页/清单。角色播放没有骨架、烘焙 SubViewport、GPU 读回或逐像素生成。武器/刀光沿用独立 GPU 表现，不包含在“角色零实时烘焙”的范围内。
- 深度来自源表面，阴影来自当前帧剪影；固定俯角与光照，不支持任意旋转镜头或动态重光照。尸体按地面法线摆放分层卡片，源深度与有序像素消隐保持遮挡，不是物理布娃娃。

## 工作台导出和补色

打开 `tools/art_preview.tscn` 按 F6，选择三维烘焙玩家/守卫/弓手，再将「查看」切为「3D 源模型」。右侧直接读取已保存的源场景，左侧保留同一帧的像素图；动作、朝向、帧、相对移动方向与上下身选择同步。左键拖动观察窗旋转、滚轮缩放，「复位视角」回到烘焙斜角。自由观察角度不会修改朝向列或图集。

三维预览仅查看身体，不含独立剑盾弓，也不显示手绘补色；原尺寸导出和回导按钮仍操作像素图。旧二维角色、箭矢来源禁用三维选项。源文件修改后保存并重开 F6 查看；像素图要重新烘焙才更新。预览能力由来源的 `model_preview()` 提供，独立的 `tools/art_model_preview.gd` 管理模型和相机；切回图集停止三维视口绘制，不进入 F5 游戏。

「完整合成」按深度合并上下身，用于查看/导出；「上身」「下身」导出原始 64×64 格，可编辑 PNG 配色/纹理，保留 JSON 后载入、应用，下次 F5 生效。握点标记不写进图片，可单独修正。

深度不由手绘颜色推断，回导不接受原轮廓之外的新不透明像素；改变形体请修改源模型后重新烘焙。完整合成图不能直接覆盖分层帧，界面会提示切换层。

一个上身可能被多个步态共用。JSON 的 key 标识预览格，binding 标识实际图层；两者须保留。同名 binding 格子必须保持相同颜色与握点，否则拒绝回导，避免最后一格悄悄覆盖前面。只改共用上身时，选择对应静态持械动作更方便。

新覆盖使用 player_baked/guard_baked/archer_baked 命名空间，与旧二维及箭矢稿隔离。已有二维精确帧覆盖仍优先生效，其余状态使用新烘焙外观；旧来源继续保留在工作台，可按资产恢复覆盖。
