# 武器三维转像素：源模型、正式接入与对照工具

## 查看与操作

用户认可风格方向后，F5 已默认接入玩家三种刀剑、弓、守卫剑盾、弓手弓及刀光。打开 `tools/weapon_pixel_lab.tscn`，按 **F6** 可做单独对照：**1/2/3** 切换宝剑/大砍刀/匕首，**Tab** 切换三维原版/平面像素。WASD、鼠标攻击、C 蹲、空格跳仍走正式玩家代码。**V** 导出当前透明 PNG 与对应深度 PNG 到 `work/weapon_pixels/`。对照场景无敌人，不读写真实进度。

运行 `tests/tactical/pixel_weapon_test.gd` 会生成三种刀剑的 **12 列朝向 × 9 行攻击相位**图集（单格 128×128）、深度图与 `atlas.json`；握柄固定在每格 (64,64)，空白容纳整圈旋转。`comparison.png` 左列原版、右列像素版；`detailed_sources.png` 查看五类源模型，`enemy_equipment.png` 查看实景剑盾与弓，`trail_*.png` 核对刀光遮挡。文件是查看与烘焙证据，不接入现有人物图集回导协议，不应把深度图作为颜色手绘稿导入。

## 借鉴的原理与本轮范围

Thomas Vasseur 的[作者技术说明](https://www.gamedeveloper.com/production/art-design-deep-dive-using-a-3d-pipeline-for-2d-animation-in-i-dead-cells-i-)描述了《死亡细胞》的三维模型/骨架动画、小尺寸无抗锯齿渲染、逐帧 PNG 与法线输出，以及卡通光照。这里复用“用三维源模型生成二维像素帧”的思路，没有复制游戏资产。

当前是 **GPU 小尺寸出图 + CPU 离线导出**，并非离线法线图管线：最终姿态在 128×128 的无抗锯齿网格生成颜色与深度，通过最近邻采样和分段明暗显示。像素密度仍为 0.04m/像素，与现有人物纸片相近。刀剑源模型增加双面刃面、暗槽、铜色基部/护手、缠带及尾饰；盾增加木板、金属边、护脐和铆钉；弓增加绑线与握柄缠带。装饰按一像素附近的尺寸设计，保留原主体轮廓、握柄、伤害和动作时序。

## 模块与数据流

- `player_combat` 在建弓和换近战模型时调用 `PixelWeaponVisual.attach`；`enemy` 在创建剑/弓/盾模型时调用同一入口。关卡显式传入相机和太阳，原握点、攻击窗口、拖地与命中流程不变。
- `weapon_sprite_baker.geometry()` 展开网格/装饰件；`bake()` 输入三角形、相机相对变换和来光方向，在像素中心正交光栅化，输出颜色与相对握柄的深度。当前凸刀身/盒体/双面面板统一绕序后剔除不可见背面；开放刀光不剔除。接入任意凹模型前须单独校验，不能把当前凸几何规则当通用网格导入器。
- `pixel_weapon` 随源模型创建/释放，用一个四边形显示像素。最终姿态交给 `pixel_frame_gpu`：一个独立 SubViewport 中合批渲染颜色和深度，放在 256×128 纹理左右两半；仅姿态/几何/光向改变时更新，屏外和隐藏时暂停。日常旋转只提交变换，不生成 Image、不上传新纹理、不读回 GPU。关闭恢复原模，原实体继续投影。
- `capture_frame()` 是显式的 CPU 导出入口，同款/同姿态的离线结果共用最多 128 帧缓存；游戏刷新绝不调用它。保留独立软件光栅器作为导出与 GPU 结果的对照依据。
- `set_bow_draw` 把弦形分为与身体相符的九相位，通过 `pixel_revision` 更新几何/缓存键。`NockedArrow` 已是透明像素素材，通过 `pixel_bake_ignore` 保留原贴图与位移，不把它烘焙成无纹理矩形。
- `swing_trail` 保留世界刀刃采样及四帧寿命，向同一 GPU 后端提交短带；新段明亮、旧段按固定像素格消退。源轨迹网格留给几何检查，本体不重复显示；刀光仍受三维深度遮挡。
- `pixel_weapon.gdshader` 从 RG 两通道解码逐像素深度，经引擎投影矩阵写入深度缓冲；所以刀柄、刀尖可以分别处于墙前/墙后。使用 [Godot 空间 Shader 的 DEPTH 接口](https://docs.godotengine.org/en/4.7/tutorials/shaders/shader_reference/spatial_shader.html)，按 Compatibility 的裁剪坐标范围转换，不用置顶材质。
- `weapon_pixel_lab` 只负责对照装配、换装和导出，直接复用正式适配器，避免叠加两张纸片。没有新增 Autoload 或保存字段。

## 验证与边界

`pixel_weapon_test` 覆盖三种刀剑各 108 个姿态、CPU 导出缓存淘汰/共享、屏外恢复、原版切换、握点、PNG 导出、连续移动攻击/蹲/跳、五名敌人的武器、弓弦/展示箭及死亡隐藏。渲染模式额外核对局部墙挡、刀光消退和五种源模型十二朝向的 GPU/CPU 轮廓、颜色及深度；正式刷新不得填充 CPU 图像缓存。

上版把逐像素 CPU 烘焙直接放入实时 `_process`，姿态变化时反复生成图片和纹理，多敌人/刀光会叠加成本。30Hz 和缓存不足以解决连续新姿态的开销，本轮已移除该热路径。固定五敌人转向、玩家重刀、四道刀光，1280×720 Compatibility、关闭 VSync/帧率上限、预热 120 帧后测 600 帧：本机最终复测帧间隔中位 9.223→5.067ms，P95 11.694→7.977ms，与初测改善方向一致。数据来自独立渲染进程的固定压力场景，不是用户实战帧率承诺；原始记录在 `work/pixel_perf_before.json` / `work/pixel_perf_confirm.json`。

像素细边仍可能跳格，太阳方向分段着色尚未包含法线贴图和局部灯光/阴影接收。无头验证不具备 GPU 成像证据；主观流畅度仍需用户实战确认。

风格方向已获认可，本轮敌方装备、源模型细节与像素刀光仍待用户试玩；离线批量烘焙、法线与武器手绘回导另行决定。

## 当前武器操作与小院战斗（2026-09-20）

武器仍由 `weapon_art.gd` 生成三维网格，经 GPU 实时输出颜色/深度；SVG 只用于 UI。宝剑与断剑使用保存的玩家横劈/过顶下劈动作，与武器旋转曲线共享相位；不再使用旧突刺作为主攻击。

`data/weapons/oath_blade.tres` 的 `finisher_hits=3` 表示三次有效敌人命中后，下一次攻击释放光刃。空挥、打墙、被盾挡不蓄能；一次挥击最多计一次，光刃不为自身蓄能。释放起手即消耗，切装/死亡清零。前摇补全剑刃，收招缩回；`pixel_unlit` 只让魔法刃免受光变暗，仍写深度，不照亮环境。

独立弓通过第五槽装备，左键发箭；所有武器右键按住格挡，正面 120 度减伤 75%，侧后方不减伤，格挡时减速且不能攻击。Alt 翻滚保留物理碰撞、0.56 秒动作与 0.9 秒起手间隔，仅 0.06–0.34 秒区间免伤；空中及攻击期间不能起滚。空格跳跃不变。

背包与底栏使用圆角正方形图标格，共用库存接口：1 猎刀、2 宝剑、3 重刀、4 断剑、5 弓。未获得的武器不能切换；稳定 ID 补发断剑和弓，满包不覆盖旧物品，v1 存档格式不变。新玩法入口 `scenes/courtyard_combat.tscn` 为 F5 默认；美术实验小院仍保留原数字定位。

`courtyard_combat` 覆盖实际命中蓄能、独立弓/格挡/翻滚、墙碰撞、五格 UI 和暂停；`melee_aoe` 检查光刃距离与隔墙；GPU 模式保存动作八帧与界面截图于 `work/combat_*`。主观手感由用户试玩验收。
