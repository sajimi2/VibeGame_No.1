## T01 — 第一个具体工作包
目标：Godot 运行后可用 WASD 在障碍物测试场移动，鼠标决定朝向，相机跟随。场景必须说明战斗尚未实现。
步骤：
1. 检查引擎版本，运行原始 check.ps1，记录基线；配置 DESIGN 中的 InputMap。
2. 创建独立 player.tscn（CharacterBody2D）、碰撞体、占位视觉和 Camera2D；创建移动/输入组件。
3. 实现 ActorCommandPort 的基础实现，仅 IDLE/MOVE 可用。所有 request_action 返回 false，不扣体力，不伪造战斗。将来 T02 扩展同一实现。
4. 输入适配器调用 set_intent，将屏幕鼠标转换成世界方向；移动用 move_and_slide 与 delta/速度正确配合。
5. 创建 arena.tscn，边界墙、中央障碍、出生点、操作提示；替换主场景。
6. 运行导入/启动检查，实际验证移动和碰撞，记录报告。
验收：水平/斜向同速；松键停止；长按推墙不能穿过；相机移动后瞄准仍正确；窗口缩放不改变移速；无脚本错误。
自动证据：新增移动方向归一化测试，或可复现的固定物理步模拟，证明斜向不会获得 sqrt(2) 速度。手动证据需说明实际操作，不能只写“应该正常”。
不做：攻击、敌人、背包、存档、最终美术。完成到 READY_FOR_REVIEW 即停止。

## T02 — 最小战斗闭环
实现 CombatantPort、完整行动状态、轻/重击、闪避、方向格挡；一名近战盗匪；HUD 和死亡重试。
先做受击木桩验证 ACTIVE 窗和伤害，再加入敌人追击/前摇/攻击/收招。敌人只能通过公共命中入口伤害玩家。
验收：前摇/收招不伤人；一次挥击同目标一次伤害；两个目标都可命中；体力不足拒绝动作且不改变状态；连续点击不能绕过收招；闪避无敌窗外可受伤、不可穿墙；前方挡住、背后受伤、低体力破防；死亡只发一次信号。
自动测试必须覆盖体力拒绝无副作用、重复命中、死亡一次性、无敌窗边界；手动测试覆盖前摇可读性与动作节奏。无头业务测试必须非零退出表示失败，不只打印文字。

## T03 — 敌人组合
加入弓箭手（瞄准提示/投射物/视线遮挡）、野兽（短距离突进）和三组固定遭遇；2～3 个敌人形成威胁。
验收：墙挡角色与箭；墙后敌人不隔墙发起有效攻击；离开活动区后有明确归位/脱战逻辑；重试清除旧敌人和弹丸；无无限追击或重复奖励。

## T04 — 装备
实现 InventoryPort、12 个物品定义、普通/优质生成和掉落物交互；20 格背包、四槽装备；固定盾。
使用可注入 RandomNumberGenerator，测试固定种子复现。装备实例 ID 唯一，定义资源不可被随机词条修改。
验收：满包拾取失败掉落仍在；重复拾取无复制；槽位不匹配无副作用；满包换装仍原子交换；穿脱十次属性无漂移；UI 能比较当前与候选属性。

## T05 — 成长
Codex 先补定 spend_point 接口和加点枚举，再由 Harness 实现 ProgressionPort、死亡一次发奖、升级选择。
验收：一次奖励跨多级不丢经验；每级事件仅一次；重复死亡不发奖；满级不死循环；加点不免费治疗；负数/无点请求拒绝无副作用。

## T06 — 冒险与像素呈现
做村庄契约交互、林地、两层哨站、使用既有行为组合的头目、回村领奖；村庄补满状态，无商店经济。
统一像素视觉、受击/出招反馈和必要音效；记录素材许可。任务使用未接/进行中/可交付/已完成状态，完成奖只发一次。
验收：从新游戏走完整流程；回城再进地牢不重复发完成奖；死亡与重试均可继续；暂停/背包不漏操作；记录真实通关时长与用户反馈。

## T07 — 存档与导出
Codex 先补定 schema v1、保存接口及校验策略。保存到 user://，包含角色成长、装备实例、任务状态，加载至村庄安全点；不持久化活动弹丸、实例 ID 或战斗状态。
验收：保存再加载等价；损坏/未知版本存档给可恢复反馈且不覆写原文件；临时写入后替换策略；检查匹配引擎的 Windows 导出模板，新增 Windows Desktop preset 并导出 Release。
实际运行导出的 EXE，验证中文字体、素材、输入、存档、重启读档。记录导出命令与生成文件；未安装模板时明确阻塞，禁止声称已导出。使用单独测试存档，不覆盖用户正式存档。
