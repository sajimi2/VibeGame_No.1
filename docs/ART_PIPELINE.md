# 当前美术资产与修改入口

本工程当前以程序生成美术为默认来源。GDScript 与 Shader 生成纹理和网格；人物、箭矢也可通过图集工作台导出 PNG、手绘修改，再回导为游戏使用的覆盖资源。尚无 Aseprite 工程或 Blender 骨架。`docs/art_reference/` 只保存参考图，不是游戏使用的成品素材。

| 内容 | 源文件 | 运行时形式 |
| --- | --- | --- |

| 人物与树的像素外观 | `scripts/presentation/directional_art.gd` | 32×48 人物、48×64 树纹理，缓存后交给 Sprite3D |
| 人物深度与剪影投影 | `scripts/presentation/character_billboard.gd` | 竖直纸片、俯角尺寸补偿、同帧透明剪影投影 |

## 本轮人物调整

- 头部约 7 像素高，取代原先约 14 像素的方头；提高腰线、加长上下腿、缩窄肩腰，向成人比例靠拢。玩家与敌人共用比例，仍为十二朝向。
- 玩家下蹲在约 0.16 秒内经过六级姿态变化，实际改变膝、胯、躯干和手臂位置；包含蹲行，蹲起不改变整张纸片的缩放。相机俯角有固定投影尺寸补偿，与姿态无关。敌人没有新增下蹲行为。碰撞即时响应原有规则，头顶受阻仍不能站起。
- `Pose.build()` 同时给人物绘制与持械提供手心坐标。战斗更新本帧动作后刷新纸片，`Pose.world_grip()` 把该手心投回世界位置；待机垂剑与攻击平举平滑衔接，刀光采样实际剑刃端点。
- 伤害、射程、攻击窗口、箭矢物理起点和物品数值不变；本轮修改的是表现数据。美术关节不是伤害骨骼，也不参与物理求解。

## 石材统一方式与边界

用户选择保留当前人物、树的细度。石材采用相近的纹理像素密度、少量连贯色块、裂纹与苔色、四档直接光照；巨石显示法线平滑，去掉逐三角形着色带来的碎面感。几何顶点、碰撞、地图布局与导航不变，仍参与真实三维遮挡和太阳阴影。

上述材质阶段保留了原碰撞；随后用户报告贴石卡住，现已单独修复移动碰撞，详见下节。石材外观和地图摆放保持已验收版本。

这属于“保留三维形状，局部统一像素材质与光照”的方案；没有加整幅画面降分辨率或模糊滤镜。几何外轮廓仍由原生分辨率栅格化，尚不是逐像素手绘或烘焙精修的石块剪影。之后是否需要少量精修贴图，由实际画面反馈决定。

## 移动、碰撞与遮挡修正 · 2026-09-18

- Shift 站立疾跑：4.2 → 6.8m/s，蹲行仍为 2m/s；Ctrl 临时关闭射击辅助。步行八相位保持原样，新增十二朝向疾跑八相位：加大前后腿摆幅、抬膝和躯干前倾，步态仍由实际位移驱动，顶墙不原地跑。攻击姿态继续优先控制上肢。
- 起跳初速 5.3 → 6.6m/s，重力仍为 20m/s²，固定帧实测跳高约 1.05m；十二朝向包含蹬地、收腿上升、顶点、伸腿下落、落地缓冲五段。保留空中转向限制、禁止连跳、头顶阻挡和不能直接跳上 2m 高台的约束。
- 原巨石碰撞由三层九边形扰动环与顶/底封面直接 `create_trimesh_shape()`；它是带倒扣和凹槽的三角壳，底面又与地板重合。卡死轨迹中 `move_and_slide()` 六次接触都重复返回地板法线，反向输入没有位移。240 条站立/下蹲进退轨迹原有 66 条失败。
- 现在从原顶点生成实心凸包，并把外凸顶点向下补到地面以下 0.08m，填平容易钻入的下沿；它不是任意放大的包围盒。`MovementBody` 单用第六碰撞层（值 32），玩家/敌人移动和导航均查询 `1 | 32`。原三角壳保留在视线/阻弹层（值 4/8），敌方箭矢也不会误击移动凸包。测试覆盖 240 条玩家进退、40 条实际守卫绕石返回和 10 次石面射线，290/290 通过。
- 原人物 `BILLBOARD_ENABLED` 会随镜头俯角倾斜，上半身在世界里向后延伸，贴墙时钻进墙面。改为 `BILLBOARD_FIXED_Y`，只绕竖轴；高度乘 `1 / camera.global_basis.y.y` 补偿投影，保留原屏幕比例。世界握点按同一竖直基准反算。本体继续深度测试，只有原有遮挡轮廓忽略深度。
- 去掉人物胶囊投影，改为当前帧透明剪影的 `SHADOWS_ONLY` 副本；头、手、腿及蹲跑跳姿态参与太阳投影，剑和盾继续使用各自网格投影。它仍是像素纸片剪影，不是另建一套三维人体骨架；脚底小接触阴影继续贴合地形。
- 对照探针恢复旧纸片模式后复现墙前身体被切掉；新模式在相同墙前/墙后用例中，墙前本体采样 418/418 保留，墙后仅 217/418 保留（露出墙上的部分）。已查看实际站立、下蹲阴影及墙前/墙后截图。

反思：视觉三角面适合精确射线，却不一定适合胶囊沿边滑动；“外观和碰撞顶点一致”不足以证明通行稳定。纸片屏幕上比例正确也不代表三维深度正确。现在分别回归贴边退让、真实 AI 路径和渲染遮挡，不再仅检查碰撞节点/阴影节点存在。

## 调研依据与取舍

- [Thomas Vasseur：Dead Cells 的 3D → 2D 动画制作流程](https://www.gamedeveloper.com/production/art-design-deep-dive-using-a-3d-pipeline-for-2d-animation-in-i-dead-cells-i-)：简单模型与骨架、关键姿态、低分辨率无抗锯齿输出，便于复用和反复调整武器动作。这是制作管线资料，不能据此推断其战斗世界采用三维解算。本工程借鉴共享姿态、握点和可重生成帧的思路，未引入完整离线建模/烘焙工具链。
- [Atomic Kraken：Slice Back 的像素美术流程](https://atomic-kraken.itch.io/slice-back/devlog/94965/behind-the-scenes-pixel-art-in-unreal-engine-4)：把角色帧、场景贴图和实时光照结合，强调像素尺度、有限阴影色阶和素材复用。说明风格统一不能只靠给低模套一个后处理。
- [David Holland：Godot 中的 3D Pixel Art Rendering](https://www.davidhol.land/articles/3d-pixel-art-rendering/)：组合轮廓、分档光照和相机像素对齐，并讨论移动时像素游移。文章使用特定自定义引擎版本；这里采用可在当前 Compatibility 下验证的局部材质方案，不照搬需要引擎改造的完整效果。

## 查看预览

### 人工操作入口

在 Godot 文件系统面板双击 `tools/art_preview.tscn`，按 **F6（运行当前场景）**；F5 仍进入战场。工具通过资产来源接口取帧，不加载关卡和进度存档。

1. 选择玩家、守卫、弓手或箭矢。人物可选站立、行走、疾跑、跳跃、蹲起、蹲行，以及 25 个挥砍手臂相位、9 个拉弓相位；相对移动方向、上肢和重心由下方选项控制。敌人可预览通用人形动作，不代表 AI 新增了疾跑/下蹲行为。
2. 人物图集横向为 12 个身体朝向（0～11），纵向为动作帧。点击单格暂停放大，支持逐帧、播放、整数倍缩放和滚动。箭矢为单张 **32×12** 侧影，朝向/俯仰由三维节点旋转，不需要画十二份相同侧影。
3. 点击“导出原尺寸 PNG + JSON”，两份同名文件保存在 `work/art_atlases/`；“打开导出目录”便于交给画图软件。人物每格 **32×48**、12 列，行走/疾跑 384×384、跳跃 384×240、蹲起 384×336。导出透明背景，无网格/选框/握点标记，时间戳避免覆盖旧手绘稿。
4. 用像素编辑器修改 PNG，保持画布尺寸、格子顺序和透明背景；PNG 与 JSON 留在同一目录。只修改图片时不需要手动改 JSON，文件名保持原样。
5. 工作台点“载入编辑稿 JSON”，选择对应清单，先预览；手的位置变动时，勾选“点击大图修正本帧握点”，逐格点手心。检查后点“应用当前图集到游戏”。该按钮会另存当前稿，并把纹理和握点写入 `data/art_overrides/`。
6. 停止工作台，**F5 重新运行战场**。覆盖持久化到工程资源，不依赖编辑器或工作台进程的缓存；已运行的另一游戏进程须重启。恢复时选资产，再点“恢复该资产程序外观”，只取消该资产的覆盖，其他资产和导出原稿保留。

跳跃预览按等时长循环五段姿态；游戏中的切换仍由垂直速度与落地状态决定。预览本体不包含单独的剑、弓和盾；弓手显示基础纹理，游戏原有绿色调制仍会叠加。切换资产/动作/选项会重建预览，未应用的编辑稿应先导出保留。

### 图集从哪里来，怎样改才会影响游戏

调用链是 `character_pose.build()` 生成关节 → `directional_art.texture()` 绘成 32×48 的 `ImageTexture` → 游戏用 `Sprite3D` 显示。预览/测试再次调用同一函数，取 `get_image()` 的像素，再用 `Image.blit_rect()` 按朝向/帧拼图、`save_png()` 写到硬盘。之前聊天中的跑步图来自 `locomotion_art_test.gd.atlas()`，额外做了 2 倍最近邻放大便于查看；预览器的导出保持原始像素尺寸。

- 每次导出覆盖的是**当前选项组合**的所有列/行，例如“疾跑 + 反向后退 + 持剑待机 + 中立重心”。它不会自动替换同向疾跑、挥刀中疾跑或其他动作。缺少的帧继续程序生成，已覆盖的重叠帧由最新回导优先；可逐次回导积累手绘范围。
- JSON 保存资产 ID、动作、选项、每格稳定帧键和握点。不要手动重排 `key`；工作台会检查来源、动作、尺寸、帧键、重复项和锚点。出错时保留当前预览和已有有效覆盖，不静默拉伸图像。
- 未覆盖帧仍能通过修改 `character_pose.gd` 关节/摆幅或 `directional_art.gd` 绘制逻辑统一调整；已回导帧优先使用手绘结果。要查看新的程序画法，应先取消该资产覆盖。
- 身体、轮廓和剪影阴影取同一解析后的帧，持械位置读取同一份握点。回导不会改变碰撞胶囊、伤害或攻击时序；大幅改变人物身材时，物理体积仍需另行设计。
- `work/art_atlases/` 是忽略目录，手绘原稿应自行保存；有效 `.res` 包含 PNG 字节，可随工程版本管理，当前 `all_resources` 导出规则会收集这些资源。历史 bundle 暂不自动删除，以免丢失手绘记录；恢复按钮只移除目录引用。

### 新角色/敌人的接入边界

`atlas_source.gd` 类似 C 的函数接口：字段是资产 ID、标题、单帧尺寸、朝向数；`animations()` / `options()` / `sample()` 描述动作、选项并返回 `{key, texture, anchors}`。`atlas_document.gd` 负责拼图/校验/导出；`atlas_store.gd` 只负责帧键索引和资源持久化；UI 不认识角色类型。

新增相同人形规格的敌人时，复制 `data/art_sources/02_guard.tres`，设置唯一 `asset_id` 和标题，并把该敌人的 `art_id` 设成相同值。工作台会自动发现资源，回导帧只影响这个 ID，无需增加 UI 分支。玩家也有 `art_id` 字段。来源资源本身不负责生成敌人或新增 AI。

不同尺寸/姿态体系的非人形资产需要实现自己的来源适配器，并在实际表现代码中调用 `atlas_store.lookup(asset_id,key)`；可参考 `arrow_source.gd` 与 `arrow_art.gd`。不能仅改标题就让人形演员支持任意尺寸/骨架。

### 箭矢附着修复与反思 · 2026-09-18

原 `arrow.gd` 命中后只设置 `stopped=true`，因此位置永远停在世界坐标。守卫根节点又不随身体转向，简单改成角色子节点仍不能跟随 `facing`。现在 `impact_attachment.gd` 保存相对变换，每帧晚于角色移动更新：盾挡取盾节点，身体取角色提供的朝向坐标系；箭根原点始终为箭尖，旋转整支箭而非绕偏移的箭杆中心。

胶囊是伤害判定几何，不能直接当视觉附着面。盾箭落到实际盾面范围；身体箭深入纸片主体附近，避免转侧面时箭尖悬在胶囊外壳。没有修改命中点记录、伤害或远程受击警觉。当前身体附着是根位置/朝向级别，并非逐肢体蒙皮。

飞行箭和搭弓箭共用 `arrow_art.gd` 的金属箭头、木杆、尾羽侧影。交叉裁剪面正常写入深度，与人物、盾、墙和其他三维物体互相遮挡；没有使用置顶图层。角色身上的箭保留到死亡或卸载，此时随消失的站立外观清理；飞行箭/环境箭仍为五秒寿命。

反思：仅检查“箭停下并造成伤害”遗漏了命中后的依附生命周期；仅跟随根节点又会漏掉朝向字段；仅通过变换测试仍会遗漏纸片和胶囊厚度差。新增回归同时覆盖实际射击、移动转身、最终截图与墙前/墙后像素，而不只检查节点或材质开关。

## 后退跳膝盖反弯修复 · 2026-09-18

`character_pose.build()` 原本把膝盖偏移也乘了 `travel_axis`；当鼠标朝向与移动方向相反时，髋踝连线上的膝盖便折向身体背面。现脚的摆动仍参考移动方向，膝盖偏移固定在身体局部 +Z（胸口与脚尖前方），最后和全身一起按瞄准朝向投影；疾跑的同类问题同时修正。没有修改移动、跳高、碰撞或攻击数据。

漏测原因：旧图集只传 `move_direction == direction`，帧数/纹理差异检查也未约束关节方向。新增身体 12 × 移动 12 ×（跳跃 5 + 疾跑 8）共 1872 个姿态、双腿折向检查；按身体方向汇总的 24 项修复前全部失败、修复后全部通过。另用实际鼠标事件覆盖后退跳和空中转向，并查看渲染截图。预览器现在也能直接选择“反向后退”，方便人工复核。
