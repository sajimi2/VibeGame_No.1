# 环境资产与屋顶透视

当前方向是中世纪边境驿站：灰泥木骨建筑、灰绿石墙、瓦顶、木架坡桥、低对比草地与土路。人物、像素树和已认可的巨石继续沿用。场景仍在真实三维空间中计算碰撞、深度和太阳阴影；环境通过固定密度的最近邻纹理和分段光照统一像素质感，没有把整个窗口缩成低分辨率。

## 资产入口

| 路径 | 内容与修改方式 |
| --- | --- |
| `assets/environment/textures/*.png` | 11 张 128×128 可编辑纹理：草地、土路、土壤、砖石、灰泥、木板、木梁、木材、瓦片、布、铁。可以直接修改 PNG，Godot 重新导入后生效 |
| `assets/environment/materials/*.tres` | 共用材质，选择纹理与世界像素密度；默认每米 25 纹素 |
| `assets/environment/prefabs/*.tscn` | building、wall、tower、crate、wagon、bridge 六种可调尺寸的美术构件 |
| `tools/environment_preview.tscn` | F6 查看六种构件；无敌人、任务或存档。该工具展示外观，不是碰撞试验场 |
| `tools/build_environment_textures.gd` | 当前纹理的离线生成工具。仅显式执行时覆盖上述 PNG 和材质；手绘修改后不要随意重跑 |

纹理生成命令：`Godot --headless --path <工程目录> --script res://tools/build_environment_textures.gd`。日常游戏启动不会运行生成工具，也不会生成纹理缓存。生成后让编辑器重新导入。

## 构件如何接入地图

`presentation/environment_library` 只按材质 ID 加载并缓存磁盘资源，不读取玩家或关卡状态。`environment_surface` 负责世界坐标主轴贴图和分段光照；没有逐帧 CPU 纹理绘制。

`presentation/architecture_piece` 接收 `kind / extent / rise / include_base`，只生成外观。同材质的小木梁、板面、窗框合并成网格，建好后不逐帧重建。它不创建碰撞、敌人、导航或任务。修改尺寸时在编辑器中重新生成；不要手工编辑其生成子节点。

- 独立 prefab 默认包含底层墙体或箱体。用于关卡时另配明确的 `StaticBody3D` 与碰撞形状。
- 驿站现有墙体下面的 `ArtFinish` 设置 `include_base=false`，只为已有基础网格补梁柱、石脚线、窗框等细节；碰撞仍由原父节点管理。
- 木骨墙端柱向墙端外包 0.03m、上下各超出墙芯 0.02m，避免木材与灰泥端面共面。不能把端柱重新做成与墙芯完全齐平；实际相机移动会触发深度争抢。此包边只影响美术，碰撞仍由墙体负责。
- 桥的原点是坡脚中心，朝本地 **-Z** 上升，`extent.x` 是宽度、`extent.z` 是水平长度、`rise` 是高差。板面贴合原连续坡碰撞；扶栏、梁柱是视觉细节。
- 荒堡与高度试验场通过 `terrain_builder` 共用相同材质和坡桥生成。新增地图继续调用其构造接口，不复制纹理生成代码。

现阶段木桥是斜坡的外观替换：桥下仍是原实心碰撞，未开放桥上/桥下两层行走；扶栏不新增阻挡。导航仍只支持每个 X/Z 网格一个行走表面。角色、门洞、路宽和敌人站位保持原值。

## 局部灰色与两类透视圆

墙圆只作用于实际挡住身体的构件，落在圆内本身不是淡化资格。地图中一段墙以最近的物理父节点归组，墙身、压顶、窗框一起淡化；相邻独立墙段即使共用相同石材也分别判断。独立美术预制件按 `architecture_piece` 归组，散放网格各自判断。请勿把建筑内外所有墙都挂进同一个物理节点，否则会失去逐墙段筛选边界。切换遮挡物时旧构件会经过短暂缓冲后恢复；透视半径及近墙深度柔边只控制已经获准淡化的构件。

小遮挡保留局部灰色提示；当普通墙柱/巨石合计遮住玩家约 90% 的当前身体轮廓，额外打开与屋顶圆同尺寸的墙体圆。中心约 0.91m 完全透出，向外平滑增加到 22% 墙面覆盖，再在外缘恢复正常墙体；让人物附近清晰，同时保留周围墙的位置。屋顶圆仍是中心完全透出；室内整顶淡化另行叠加。低于 80% 才关闭墙圆，附带渐变和退出缓冲。两种圆默认半径均为 3.375m，较上一版放大 50%，柔边为 1.275m。

墙圆由 `presentation/wall_occlusion.gd` 管理，`body_occlusion_probe` 从当前身体图集颜色/深度做离散面积采样；上、下身重叠仅计一次，使用未淡化的真实三角面检查，不以物理碰撞盒或已开孔画面计算比例。每秒检查 10 次，静态图页缓存一次，不逐帧读屏。它接管两种实心环境材质 `environment_surface` / `pixel_stone`；草地、路面、明确标记的承托结构和屋顶排除，Sprite3D 树与其他透明材质仍只使用原灰色提示。新动态环境生成后调用 `register_branch(子树)`；任意新材质不能未经适配直接套用。

**承托用途必须显式声明**：在地板、高台、桥面所属节点的 Metadata 中添加字符串 `occlusion_role = support`，子节点自动继承，包括顶面、侧壁与支架。驿站已标记地面、高台、两座坡桥与三栋地板；`terrain_builder` 的高台/坡道和 `architecture_piece` 的桥构件也自动保护。新增石砌台阶/木平台应同样标记，不能因为它和墙共用石材/木材就套用透视。墙帽、横梁、石脚线不受厚度过滤，要与墙身共同透视；禁止恢复“低于 0.25m 一概排除”的判断，它会留下悬浮的薄面。支持角色跳上去的未来可透视物件，应另外明确其承托策略。

共同默认值在 `presentation/occlusion_style.gd`，`CLEAR_CORE_FRACTION` 控制墙圆全透核心占半径的比例；运行时 `WallOcclusion` 的 `Enter Ratio / Exit Ratio` 调触发与退出阈值。有屋顶遮挡时墙圆沿用该屋顶实际半径、柔边和 `Indoor Opacity`，保证两层重合；无屋顶时用共享默认值。透视显示使用材质副本与稳定像素覆盖裁切，阴影代理仍使用完整原材质；不更改物理、视线和弹道。

两种 Shader 共用 `occlusion_depth.gdshaderinc` 的深度柔边：人物附近留 0.85m 身体/墙厚余量，再经过 1m 逐渐恢复后方表面。不要改回 `dot(...) > 0.03` 的硬分支；贴近厚墙、转角或斜屋面时，它会在圆内切出直线折角。此余量仅影响局部显示，远后方墙体仍保持不透明；屋顶是否触发仍由原视线检测负责。

原问题来自两条判定都漏过屋檐：旧渐隐只认建筑地面范围，角色描边射线又不检测没有碰撞体的屋面。人在地面范围外仍可能被正交镜头前方的屋顶挡住。

`interior_roof` 由关卡注入玩家。它从当前相机分别检查玩家脚、胸、头到屋面网格的视线，不用室内 AABB 决定是否开孔。当前屋顶是旋转的薄 `BoxMesh`，在各网格局部用包围盒检测就是其精确盒形；未来改成带缺口的任意屋顶模型时须同步更换遮挡形状，不能直接沿用整模型 AABB。

发现遮挡后，独立屋顶材质在角色屏幕位置打开透视圆：半径 3.375m、边缘过渡宽 1.275m、渐变 0.28 秒，离开遮挡保留 0.13 秒缓冲。室外圆外保持不透明；进入可进入建筑的 `interior` 范围后，整组屋面再渐变到 `indoor_opacity=0.22`，圆孔叠加在这层淡屋面上。两者覆盖率相乘，整片不会被全部删除。图案锚在世界投影，避免镜头移动时网点爬动；这是一种像素覆盖率半透明，不依赖排序不稳定的整顶透明混合。

每栋屋顶保留独立、仅投影的网格代理，所以圆孔和整体淡化不会挖掉建筑的太阳阴影。不要给这个代理套用透视 Shader。`interior / can_enter` 仅决定整组淡化，不能限制视线圆孔；不可进入的塔顶与屋檐外仍能局部透视。墙体不会跟着屋顶消失。

小遮挡改用角色的灰色被挡片段，取消整身黄色描边。`baked_human` 的灰色变体读取同一帧颜色/深度图集，再与开孔后的环境深度逐像素比较；空白和可见部分直接丢弃。灰色层优先级 -1、不写深度，正常身体随后覆盖可见的部分，避免手与躯干重叠处误染。中心物理射线保留 HUD 调试状态，不控制这层的开关；不要再用“节点 visible=false”作为无遮挡的判据。死者不显示灰色提示。

在 Godot 选中 `Roofs/WarehouseRoof` 可调整 `Indoor Opacity`、`Reveal Radius`、`Feather Width`、`Fade Seconds`；调整室内范围用 `Interior`。灰色统一在 `baked_human.gdshader` 的 `occlusion_color` 设置；参数只影响显示，不改变瞄准/碰撞/敌人感知。

## 验证边界

环境精度由 `scripts/presentation/environment_pixel_pass.gd` 与同名 Shader 统一处理。当前默认每 2×2 个逻辑像素共享一个环境颜色，即 1280×720 画布下等效 640×360；F2 随时恢复原环境，暂停可用。1280×720 窗口中色块约为 2×2 屏幕像素，1920×1080 全屏约为 3×3。人物依旧使用 96² 图集和原显示精度，武器、箭矢、界面不参与该降采样；源纹理、模型与碰撞都保留。网格锚定世界的相机平面，以减少跟随镜头移动时的采样跳闪。

采样使用整数 `texelFetch` 读取每块的四个源像素并平均，随后整个块使用同色；块间不插值、不混合历史帧。不能恢复成在块中心使用归一化最近邻读取：2×2 块的中心恰是源纹素边界，浮点误差会在镜头移动时改选邻居，造成缝隙闪烁。世界网格锚定与精确源像素寻址缺一不可。平均会减弱过细缝隙的对比，但保留块状轮廓。

这是环境颜色的后处理，不是真正把整个世界放进低分辨率视口：原环境深度仍精确，角色保持深度遮挡。环境光栅化工作量尚未减少，不能据此宣称性能优化。尘土和接触阴影等透明特效仍走后续绘制；新增透明环境资产时应检查这个边界。渲染顺序约定见 ARCHITECTURE.md。

`environment_resolution_test.gd` 在真实窗口/全屏下，用保留阴影的角色显示差分核对玩家和六种敌人，要求开关前后的身体/武器像素与轮廓完全一致，并实际检查环境变化和 2×2 色块；另测 F2、按键连发与暂停。原始/粗环境对照保存在 `work/environment_resolution`。

`environment_motion_test.gd` 补动态验证：冻结演员和屋顶渐变，使用生产相机对齐函数连续平移，抵消已知屏幕位移后比较同一环境表面。覆盖墙瓦/野地、横纵/斜向和窗口/全屏，原始与粗环境各测一次。记录 RGB 最大通道差异 >8/255 的像素占比，最坏帧必须低于 1%；截图和指标在 `work/environment_motion/regression`。没有真实 GPU 时明确跳过，不能用静态截图替代此检查。

`tests/tactical/environment_art_test.gd` 检查共用资源、合并网格、桥碰撞及屋檐外/下蹲/屋顶上方/恢复/多建筑独立。带实际渲染运行时比较同一画面开孔前后的像素，确认圆内改变、圆外和阴影不变；`waystation_blockout`、`waystation_combat` 与 `height_edge` 继续验证真实移动与追击。所有自动测试隔离真实存档。

`occlusion_presentation_test.gd` 实测局部灰色只落在被挡像素上、无遮挡零染色、物理射线漏检、F2 与全屏一致，以及室内整体淡影和圆孔叠加、室外只有圆孔、离开/屋上恢复。另比较实际残留屋瓦与完全剔除的画面，并检测低透明屋面移动网点的稳定性；截图位于 `work/occlusion`。

当前场景外观已接入，艺术质量和交战时的视野舒适度仍由用户试玩确认。新增建筑不需要改战斗逻辑，但若改变实体尺寸，应同步编辑碰撞并复测门洞与导航。
